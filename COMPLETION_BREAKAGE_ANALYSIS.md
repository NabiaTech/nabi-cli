# Completion Breakage Analysis

**Date**: 2025-11-18
**Status**: 🔴 **BREAKING REPEATEDLY**
**Root Cause**: Autoload function override workaround is fragile

---

## Executive Summary

Completions keep breaking because:
1. **Post-commit hook** runs `just install` → `just completions` on every commit
2. **Dynamic completion file** is appended to static completion file
3. **Autoload conflict**: zsh autoloads `_nabi`, making it a stub, not a function body
4. **Workaround approach**: Trying to save/restore autoloaded function is fragile
5. **Recent commits**: Multiple attempts to fix (ca9b2d2, 4269023, 3466d1d, e516b7e)

**Impact**: Every commit potentially breaks completions, requiring manual fixes.

---

## What Was Working (Before Recent Changes)

### Stable State (commit f6ae61a - "refactor(completions): migrate to schema-driven configuration")

**Architecture**:
- Static completions generated by clap → `.build/_nabi_static`
- Dynamic completions in `contrib/nabi-completions-dynamic.zsh`
- Merged via `justfile` line 136: `tail -n +2 contrib/nabi-completions-dynamic.zsh >> "${ZSH_COMP_FILE}"`
- Validation via `scripts/validate-completions.sh`

**How It Worked**:
1. Static file defines `_nabi()` function (lines 1-8800+)
2. Dynamic file checks `if (( $+functions[_nabi] ))` 
3. If `_nabi` exists, saves it as `_nabi_original` using `functions[_nabi_original]=$functions[_nabi]`
4. Overrides `_nabi` with new wrapper that calls `_nabi_original "$@"` for non-dynamic cases

**Why It Worked**:
- When zsh loads the completion file, `_nabi` is defined as a function (not autoloaded yet)
- `$functions[_nabi]` contains the actual function body
- Copying works because it's a real function, not an autoload stub

### The Breaking Point

**Current Error**:
```
_nabi:60: _nabi_original: function definition file not found
```

**Root Cause**:
- zsh autoloads completion functions from files
- When `_nabi` is autoloaded, `$functions[_nabi]` contains `builtin autoload -XU` (a stub)
- Copying this stub to `_nabi_original` creates an autoload stub pointing to `_nabi_original`
- But the file only defines `_nabi`, not `_nabi_original`
- When `_nabi_original` is called, zsh tries to autoload it and fails

**Why It's Fragile**:
- Depends on timing: when is `_nabi` autoloaded vs loaded?
- Depends on zsh version: different autoload behavior
- Depends on completion system state: compinit may or may not have run
- No way to reliably detect if function is autoloaded vs loaded

## Why It Keeps Breaking

### 1. Post-Commit Hook

**File**: `.git/hooks/post-commit`
```bash
just install >/dev/null 2>&1 && echo "✅ Build complete" || echo "❌ Build failed"
```

**Problem**: 
- Runs on EVERY commit
- Regenerates completions
- If completion generation has any issue, it breaks silently (output redirected)
- No validation that completions actually work

### 2. Justfile Install Chain

**File**: `justfile` line 144
```
@install: completions sign
```

**Chain**:
1. `just install` → calls `just completions`
2. `just completions` → calls `just build` → generates static completions → appends dynamic → validates
3. If validation passes but runtime fails, no one notices until user tries to use completions

### 3. Validation Doesn't Test Runtime

**File**: `scripts/validate-completions.sh`

**What It Tests**:
- ✅ Syntax validity (`bash -n`)
- ✅ Structural integrity (markers, function names)
- ✅ File size, duplicates

**What It Doesn't Test**:
- ❌ Can `_nabi` actually be called?
- ❌ Does `_nabi_original` work?
- ❌ Does autoload work correctly?
- ❌ Runtime completion behavior

### 4. Design Flaw: Overriding Autoloaded Functions

**The Core Problem**:
- zsh completion system autoloads functions from files
- We're trying to override an autoloaded function
- We're trying to save the original, but it's just a stub
- This is fundamentally incompatible

**Why It's a Workaround**:
- Proper zsh completion would use completion tags/descriptions
- Proper zsh completion would hook into `_arguments` completion functions
- We're hacking around clap's limitations by overriding the main dispatcher

## Current State Analysis

### What's Actually Happening

1. **Static completion file** (`_nabi`) defines `_nabi()` function
2. **zsh autoloads** `_nabi` from the file (makes it a stub)
3. **Dynamic file is appended** to static file
4. **Dynamic code runs** when file is sourced
5. **Dynamic code checks** `if (( $+functions[_nabi] ))` → TRUE (stub exists)
6. **Dynamic code tries to save** `functions[_nabi_original]=$functions[_nabi]` → saves stub
7. **Dynamic code overrides** `_nabi` with wrapper function
8. **Wrapper calls** `_nabi_original "$@"` → tries to autoload `_nabi_original` → FAILS

### The Fix Attempt (Current)

**File**: `contrib/nabi-completions-dynamic.zsh` lines 48-70

```zsh
if [[ "$_nabi_def" == builtin\ autoload* ]] || [[ "$_nabi_def" == *autoload* ]]; then
    _nabi_original() {
        local _saved_override="$functions[_nabi]"
        unfunction _nabi 2>/dev/null || true
        _nabi "$@"
        local ret=$?
        functions[_nabi]="$_saved_override"
        return $ret
    }
```

**Problem**: This creates a recursive wrapper that:
- Saves our override
- Removes our override
- Calls `_nabi` (which autoloads original)
- Restores our override

**Why It's Still Fragile**:
- Depends on autoload working correctly
- Creates function churn (unfunction/redefine)
- May have timing issues
- Doesn't solve the root cause

## Recommendations

### Short-Term: Stop the Bleeding

1. **Disable post-commit hook temporarily**
   ```bash
   mv .git/hooks/post-commit .git/hooks/post-commit.disabled
   ```

2. **Add runtime validation to justfile**
   ```bash
   # After completions are generated, test them
   zsh -c 'autoload -Uz compinit && compinit && _nabi 2>&1 | head -1'
   ```

3. **Revert to known-good commit**
   ```bash
   git checkout f6ae61a -- contrib/nabi-completions-dynamic.zsh
   ```

### Medium-Term: Fix the Design

1. **Don't override `_nabi`** - Instead:
   - Override specific completion functions (`_nabi__tmux__send_prompt_pane`, etc.)
   - Use zsh completion tags/descriptions
   - Hook into `_arguments` completion functions

2. **Don't append dynamic file** - Instead:
   - Source dynamic file separately after compinit
   - Use zsh's `compdef` system properly
   - Keep static and dynamic separate

3. **Use proper zsh completion patterns**:
   ```zsh
   # Instead of overriding _nabi, override specific completions
   _nabi__tmux__send_prompt() {
       local context state line
       _arguments '1: :_nabi_tmux_send_prompt_pane'
   }
   ```

### Long-Term: Proper Solution

1. **Modify clap generation** to use custom completion tags
2. **Use zsh completion system** as designed (tags, descriptions, `_arguments`)
3. **Separate static and dynamic** completions (don't merge files)
4. **Add integration tests** that actually test completion behavior
